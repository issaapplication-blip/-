## Root cause and correction

- Root cause: checked-in `bun.lock` did not reflect all dependencies in `package.json`; in particular, the workspace dependency section omitted `@kapso/whatsapp-cloud-api` and `qrcode`, causing `bun install --frozen-lockfile` to fail.
- Correction: regenerated `bun.lock` using Bun 1.3.10; the generated lock includes the missing direct dependencies and their transitive dependencies.
- Docker correction: Dockerfile now copies both `package.json` and `bun.lock`, and uses `bun install --frozen-lockfile --production`. The previous unpinned/fallback installation path is removed from the proposed Dockerfile.
- Lockfile verification: `bun install --lockfile-only`, `bun install --frozen-lockfile --dry-run`, and `bun install --frozen-lockfile` all succeeded in workflow run #2.
- Exact SHA256 values and dependency entry-count comparison are recorded in the workflow run's step summary; consult the run summary rather than inferring these values from Git object IDs.
- Version impact: the lock refresh primarily adds missing dependency entries and transitive packages. No direct dependency version bump is shown for Elysia (1.4.27), Kapso WhatsApp Cloud API (0.3.0), QRCode (1.5.4), or @types/bun (1.3.10). No deliberate major-version upgrade was performed.
